## アプリ内の処理と外部への送信

ワールドの選択・スキャン・確認はローカルで行います。AI 翻訳を実行すると、選択した原文、翻訳先の言語、翻訳指示などのリクエスト内容が、**選択した API プロバイダーまたは Custom endpoint** に送信されます。サーバー名・本・看板などに個人情報が含まれていないか確認し、翻訳対象に含めないようにしてください。受信したデータには各プロバイダーの保存・学習・削除ポリシーが適用されます。

**アップデート確認**では、GitHub (`github.com/kim0040/PomiTranslate`) から最新バージョン情報 (`latest.json`) だけを取得します。ワールド、キー、利用履歴、インストール識別子は送信しません。設定 → 更新で、1 日 1 回の自動確認を無効にできます。ヘルプ・情報画面の Web リンクは、あらかじめ定めた宛先 (GitHub、minecraft.net、プロバイダーの API キー発行ページ、問い合わせメール) だけを既定のブラウザーで開きます。

モデル対応情報と利用量の照会も、選択したプロバイダーへのネットワークリクエストを行います。OpenRouter の公開モデルカタログ照会ではキーとワールドのテキストを送信しません。利用量の照会や他のプロバイダーへの認証リクエストには保存済みのキーを使います。翻訳指示の調整は別の AI リクエストです。

**接続の確認**（設定アシスタントのキー入力の手順と、設定 → 翻訳タブの「接続を確認」）は、選択したプロバイダーにモデル一覧を問い合わせます。入力欄に入力したキーを使う場合、そのキーはこの 1 回のリクエストにだけ使い、保存ボタン（設定アシスタントでは最後の保存の手順）を押すまで保存しません。キーを入力していない場合は保存済みのキーを使います。

**用語集**はワールドフォルダーではなくアプリのデータに保存します（すべてのワールド用は設定ファイル、ワールドごとの用語集はアプリデータ内の別ファイル）。ワールドのファイルには何も書き込みません。翻訳リクエストには、そのまとまりの原文に含まれる用語の項目だけを、選択したプロバイダーへ一緒に送信します。該当する用語がないリクエストには用語集を含めません。

**完了通知**は OS の通知であり、外部には送信しません。アプリのウィンドウが背面にあるときに長い作業が終わると、ワールド名と件数・状態だけを表示し、原文・訳文・パス・キーは含めません。通知の許可は最初の通知を送るときに一度だけ求め、設定 → アプリでオフにできます。

デスクトップアプリは JSONL sidecar を使用し、UI 用の localhost サーバーを開きません。開発用 Vite サーバーと legacy Web UI は別のものであり、同じ実行構成として紹介していません。

## アプリに保存されるデータ

設定、用語集、最近使ったワールドのパス、ウィンドウのサイズと位置、モデルキャッシュ、スキャン計画・チェックポイント、翻訳レポート、バックアップはアプリデータに残る場合があります。適用を終えた作業も、後で訳文を修正できるように、訳文がチェックポイントに残ります。パス・原文・翻訳文が含まれることがあるため、診断資料や公開リポジトリにそのままアップロードしないでください。設定 → アプリタブの **初期化**では、設定、最近使ったワールド、再開可能な作業、モデル一覧を削除できます。選択した場合は保存済み API キーも削除できます。ワールドのバックアップは初期化では削除されません。削除するにはデータフォルダーを手動で削除してください。ヘルプの **診断情報をコピー** と診断のエクスポートに含まれるのは、アプリのバージョン、ビルド、OS、エラーコード、リクエストの種類・所要時間・結果コード、コアの診断行の既知の形だけです。自由テキスト (エラーメッセージ、パス、ワールド名・本文、キー) は作る時点で含めず、ローカルのログファイルにも書きません。暗号化 portable export は提供していません。アップデートやクリーンアップツールとデータの関係は、[アップデートとデータ保持 (韓国語)](updates-and-data.md) を参照してください。

公開 Python 設定パスは、macOS `~/Library/Application Support/PomiTranslate`、Windows `%APPDATA%/PomiTranslate`、Linux `$XDG_DATA_HOME/PomiTranslate` または `~/.local/share/PomiTranslate` です。ネイティブ vault は Tauri の app-data パスにある `credentials/credentials.sqlite` と `credential-key/master.key` を使用します。隔離された Eval identifier は別のルートを使用するため、通常のアプリとはデータを共有しません。

## API キー

- 既定: **ローカル暗号化保存** — Rust SQLite と AES-256-GCM、およびインストールごとに分けたキー ファイルを使用します。
- 任意: **セッションのみ** — アプリを再起動した後にキーを再入力する必要があります。
- 任意: **OS キーチェーン** — ユーザーが選択したとき、または既存キーのインポートを実行したときにアクセスします。起動時に既存キーを自動で読み込んでインポートすることはありません。

画面に表示されるのはキーの保存有無と保存方法だけで、保存済みキーの文字列は返しません。API リクエストでキーが必要な場合、Rust が stdin を通じて sidecar に渡します。公開設定 JSON やワールドバックアップにキーは含めません。

データベースと暗号化キー ファイルの両方を読み取れる同じユーザー権限のプロセスは、キーを復号できます。この設計は、悪意あるプログラム、アカウント乗っ取り、メモリや swap からの漏えいまで防ぐものとして紹介していません。これらのファイルを自動同期したり、公開バックアップに含めたりしないでください。OS アカウントとディスクも別途保護してください。アプリはデータフォルダーと vault フォルダーがリンクではなく、ユーザー所有で、他のユーザーが書き込めないことを確認しますが、同じユーザー権限で動く別のプロセスはこの確認による保護の対象外です。

CLI と legacy UI は従来の OS keyring／環境変数との互換経路を使用し、デスクトップ vault と自動で共有しません。`.env.example` は秘密情報を含まない形式例です。実際のキーを平文の `.env` に保存する方法は推奨していません。

キーの変更・削除には設定を使用してください。Local から Session／Keychain に切り替えると、アプリに残っている Local の暗号文を削除します。既存の OS キーチェーンのキーをインポートしてもコピーするだけで元の項目は残りますが、アプリはその項目があることを記録するため、キーの削除や「キーを削除」を選んだリセットのときにその項目も削除します。Local と Session の間の切り替えではキーチェーンに触れません。キー ファイルを紛失したり暗号文が破損したりした場合、キーの再入力が必要になることがあります。アプリの OS キーチェーン項目は、サービス名が `PomiTranslate` で、アカウント名がプロバイダー名（例: `openai`）のものだけです。この名前空間に書き込むのは PomiTranslate だけです。アプリはキーチェーンを列挙せず、ほかの項目には触れません。これらの項目を削除するのは、ユーザーが明示的に操作したときだけです。プロバイダーのキーの削除、そのプロバイダーを Keychain から別の保存方法へ切り替えること、「キーを削除」を選んだアプリのリセット（すべてのプロバイダー）が該当します。すでに存在しない項目は削除済みとして扱います。設定にそのプロバイダーのキーチェーン使用記録がない場合（Keychain を選んだことがない場合）、アプリはキーチェーンにアクセスしません。OS が削除を拒否した場合、アプリは項目を削除できなかったこと（`KEYCHAIN_UNCONFIRMED`）を伝え、もう一度操作すると再び削除を要求します。

**Custom サーバーのキー**は、保存した時のサーバーアドレス (スキーム・ホスト・ポート。パスは含みません) に結び付けられます。アドレスを別のサーバーに変えると、保存済みのキーは新しいサーバーへ送らず、キーの再入力を求めます (`CUSTOM_KEY_ORIGIN_MISMATCH`)。アドレスが記録される前に保存した Custom キーも、再入力が必要になることがあります。公開プロバイダーのキーを Custom サーバーへ送ることはありません。通常の `http://` はこのコンピューター (localhost・127.0.0.1 など) に限って許可され、それ以外のサーバーは `https://` が必要です (`CUSTOM_ENDPOINT_INSECURE`)。

デスクトップアプリの Python コア (JSONL) は、OS の keyring を読み書きしません。キーチェーンは Rust が上記のルールでのみ扱い、コアにはリクエストに必要なキーだけを渡します。選択したプロバイダーのキーがない場合に、別のプロバイダーの環境変数のキーで代用することもありません。CLI も、そのプロバイダー自身の環境変数・keyring の項目だけを使います。
